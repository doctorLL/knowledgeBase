# 第十三章 监控过程组

## 2. 章首速览

监控过程组回答“实际情况是否偏离计划，以及如何纠偏”：先形成工作绩效信息，再监督质量、范围、进度、成本、资源、沟通、风险、采购和干系人参与，必要时提出变更请求并更新计划与项目文件。

主线可记为：

> 测量实际绩效 → 对照计划与基准 → 识别偏差及趋势 → 预测后续结果 → 提出变更或纠偏 → 持续更新计划与记录。

## 3. 质量管理

### 3.1 控制质量

**控制质量**是为了评估绩效，确保项目输出完整、正确且满足客户期望，而监督和记录质量管理活动执行结果的过程。作用包括：核实项目可交付成果和工作已达到主要干系人的质量要求，可供最终验收；确定项目输出是否达到预期目的，并满足适用的标准、要求、法律法规和规范。

该过程在**整个项目期间**开展。敏捷或适应型项目中，控制质量活动可能由所在团队成员在整个项目生命周期中执行；瀑布或预测型项目中，通常由特定团队成员在特定时间点或项目阶段快结束时执行。

### 3.2 控制质量的工具与技术

- **数据收集**：核对单、核查表、统计抽样、问卷调查。
- **测试**：一种有组织、结构化的调查，目的是找出产品或服务中的错误、缺陷、漏洞或其他不合规问题。原稿列出单元测试、集成测试、黑盒测试、白盒测试、接口测试、回归测试和“a 测试”；末项疑似字母识别问题，待教材核对。
- **数据表现**：因果图用于识别质量缺陷和错误可能造成的结果；控制图用于确定过程是否稳定或绩效是否可预测；直方图可按来源或组成部分展示缺陷数量；散点图可分别展示计划绩效和实际绩效。原稿对因果图的“结果”表述待教材核对。
- **会议**：包括审查已批准变更请求、回顾/经验教训会议。回顾会议讨论项目或阶段成功要素、待改进之处、当前及未来项目可增加的内容，以及可增加到组织过程资产中的内容。

## 4. 范围管理

### 4.1 确认范围

**确认范围**是正式验收已完成的项目可交付成果的过程。其作用是使验收过程具有客观性，并通过确认每个可交付成果，提高最终产品、服务或成果获得验收的可能性。该过程在**整个项目期间定期开展**。

> ![[be4335945cf3b4f660b86d0ee555333d.png]]

> [!note] 原稿 ITTO（图片转写，待教材核对）
> - **输入**：项目管理计划（范围管理计划、需求管理计划、范围基准）；项目文件（经验教训登记册、质量报告、需求文件、需求跟踪矩阵）；核实的可交付成果；工作绩效数据。
> - **工具与技术**：检查；决策（投票）。
> - **输出**：验收的可交付成果、工作绩效信息、变更请求；项目文件更新（经验教训登记册、需求文件、需求跟踪矩阵）。

确认范围的一般步骤：确定范围确认时间；识别所需投入；确定正式接受的标准和要素；确定确认会议的组织步骤；组织范围确认会议。

确认范围前，团队需要先完成控制质量工作：**控制质量关注可交付成果的正确性及是否满足质量要求，确认范围关注客户或发起人对可交付成果的正式验收**。符合验收标准的可交付成果应由客户或发起人正式签字批准。

### 4.2 范围确认检查与干系人关注点

项目干系人进行范围确认时，应检查：可交付成果是否明确、可确认；是否具有明确且可辨别的里程碑事件；是否有明确质量标准；审核和承诺是否表达清晰；项目范围是否覆盖所有必要活动、有无遗漏或错误；风险是否过高、管理层能否降低风险影响。

不同干系人的关注点：管理层关注项目范围；客户关注产品范围；项目管理人员关注项目制约因素；团队成员关注项目范围中自己参与和负责的元素。

### 4.3 控制范围

**控制范围**是监督项目和产品的范围状态、管理范围基准变更的过程。其作用是在整个项目期间保持对范围基准的维护。未经控制的产品或项目范围扩大称为**范围蔓延**。

## 5. 进度管理

### 5.1 控制进度

**控制进度**是监督项目状态，以更新项目进度和管理进度基准变更的过程。其作用是在整个项目期间保持对进度基准的维护。进度基准的任何变更都必须经过实施整体变更控制过程审批。

控制进度关注：判断当前进度状态；对引起进度变更的因素施加影响；重新考虑必要的进度储备；判断进度是否发生变更；在变更实际发生时进行管理。

采用敏捷方法时还需关注：比较上一时间周期已交付并验收的工作总量与已完成工作估算值；实施回顾性审查；重新确定剩余工作优先级；确定每次迭代内可交付成果生成、核实和验收的速度；识别并管理进度变更。

### 5.2 控制进度的数据分析与压缩

- **挣值分析**：用于测量进度绩效。
- **迭代燃尽图**：追踪迭代未完项中尚待完成的工作。
- **绩效审查**：根据进度基准测量、对比和分析进度绩效。
- **趋势分析**：检查绩效随时间的变化，判断改善或恶化趋势。
- **偏差分析**：关注实际与计划的开始/完成日期、持续时间及浮动时间偏差。
- **假设情景分析**：依据风险管理过程输出评估不同情景，使进度模型符合项目管理计划和批准的基准。
- **进度压缩**：对剩余工作使用**快速跟进**或**赶工**。

### 6.1 控制成本

**控制成本**是监督项目状态，以更新项目成本和管理成本基准变更的过程。其作用是在整个项目期间保持对成本基准的维护。

> - **工具与技术**：专家判断；数据分析（挣值分析、偏差分析、趋势分析、储备分析）；完工尚需绩效指数；项目管理信息系统。

### 6.2 项目成本控制目标

项目成本控制的目标包括：对造成成本基准变更的因素施加影响；确保变更请求及时处理；在变更实际发生时管理变更；确保成本支出不超过按时段、WBS 组件、活动和项目总额分配的批准限额；监督成本绩效并分析偏差；对照资金支出监督工作绩效；防止报告未经批准的成本或资源使用变更；向干系人报告批准的变更及相关成本；将预期成本超支控制在可接受范围内。

### 6.3 挣值分析

基本指标：**PV**（计划价值）、**AC**（实际成本）、**EV**（挣值）、**BAC**（完工预算）、**EAC**（完工估算）、**ETC**（完工尚需估算）。

偏差与指数：

| 指标 | 公式 | 判读 |
|---|---|---|
| 进度偏差 SV | `EV - PV` | >0 进度超前；<0 进度落后；=0 符合计划 |
| 进度绩效指数 SPI | `EV / PV` | >1 进度超前；<1 进度落后；=1 符合计划 |
| 成本偏差 CV | `EV - AC` | >0 成本节省；<0 成本超支；=0 符合预算 |
| 成本绩效指数 CPI | `EV / AC` | >1 成本节省；<1 成本超支；=1 符合预算 |

完工估算：`EAC = AC + ETC`。

- **非典型偏差**：若当前偏差预计以后不再发生，原稿给出 `ETC = BAC - EV`。
- **典型偏差**：若当前偏差可代表未来偏差，原稿给出 `ETC = (BAC - EV) / CPI`，或 `EAC = BAC / CPI`。

### 6.4 完工尚需绩效指数

**完工尚需绩效指数（TCPI）**表示为了实现特定管理目标，剩余资源的使用必须达到的成本绩效，是完成剩余工作所需成本与剩余预算之比。原稿只给出以 BAC 为目标的公式：

> `TCPI = (BAC - EV) / (BAC - AC)`

原稿未给出以 EAC 为目标时的公式和适用条件，因此本笔记不自行补充，待教材核对。

## 7. 资源管理

### 7.1 控制资源

**控制资源**是确保按计划为项目分配实物资源，根据资源使用计划监督资源实际使用情况，并采取必要纠正措施的过程。其作用是确保资源适时适地可用于项目，并在不再需要时释放。该过程在整个项目期间开展。

控制资源关注：监督资源支出；及时识别和处理资源缺乏或剩余；按计划和项目需求使用、释放资源；出现资源问题时通知相应干系人；影响导致资源使用变更的因素；管理实际发生的变更。进度基准或成本基准的任何变更都必须经过实施整体变更控制审批。

## 10. 采购管理

### 10.1 控制采购

**控制采购**是管理采购关系、监督合同绩效、实施必要的变更和纠偏，以及关闭合同的过程。其作用是确保买卖双方履行法律协议并满足项目需求。该过程在整个项目期间开展。

> - **输入**：项目管理计划（需求、风险、采购、变更管理计划及进度基准）；项目文件（假设日志、经验教训登记册、里程碑清单、质量报告、需求文件、需求跟踪矩阵、风险登记册、干系人登记册）；协议；采购文档；批准的变更请求；工作绩效数据；事业环境因素；组织过程资产。
> - **工具与技术**：专家判断、索赔管理、数据分析（绩效审查、挣值分析、趋势分析）、检查、审计。
> - **输出**：采购关闭、工作绩效信息、采购文档更新、变更请求；项目管理计划更新（风险管理计划、采购管理计划、进度基准、成本基准）；项目文件更新（经验教训登记册、资源需求、需求跟踪矩阵、风险登记册、干系人登记册）；组织过程资产更新。

### 10.2 合同管理、索赔与采购关闭

合同管理活动包括：收集数据和管理项目记录；完善采购计划和进度计划；建立采购数据收集、分析和报告机制并编制定期报告；监督采购环境；向卖方付款。

采购文档包含管理采购过程的完整支持性记录，如工作说明书、支付信息、承包商工作绩效信息、计划、图纸和其他往来函件。

合同双方无法自行解决索赔时，可能需要按合同程序使用替代争议解决方法（ADR）；**谈判是解决所有索赔和争议的首选方法**。

原稿所列正式采购关闭要求：全部可交付成果按时、按质量和技术要求交付；没有未决索赔或发票，最终款项全部付清。

## 11. 干系人管理

### 11.1 监督干系人参与

**监督干系人参与**是监督项目干系人关系，并通过修订参与策略和计划，引导干系人合理参与项目的过程。其作用是随着项目进展和环境变化，维持或提升干系人参与活动的效率和效果。该过程在整个项目期间开展。

## 12. 章末综合复习

### 12.1 核心对比

| 易混项 | 区分 |
|---|---|
| 管理质量 / 控制质量 | 管理质量重过程与持续改进；控制质量重结果正确性、完整性与合规性 |
| 控制质量 / 确认范围 | 控制质量先核实正确性，形成核实的可交付成果；确认范围再由客户或发起人正式验收 |
| 项目范围 / 产品范围 | 管理层更关注项目范围；客户更关注产品范围 |
| 控制范围 / 控制进度 / 控制成本 | 分别维护范围、进度、成本基准，基准变更均走实施整体变更控制 |
| 工作绩效数据 / 工作绩效信息 | 执行过程产生原始数据；监控过程分析后形成信息 |
| 风险审计 / 风险审查会 | 审计评估风险管理过程有效性；审查会是监督风险的会议形式 |
| 实施采购 / 控制采购 | 实施采购选择卖方并签约；控制采购管理关系、合同绩效、变更与关闭 |

### 12.2 必须准确记忆

- 控制质量与确认范围的先后关系及两类可交付成果。
- 范围确认五步骤、六项检查和四类干系人关注点。
- 控制进度六类数据分析与两种进度压缩方法。
- `SV=EV-PV`、`SPI=EV/PV`、`CV=EV-AC`、`CPI=EV/AC`。
- 非典型偏差与典型偏差下的 ETC/EAC 公式。
- 以 BAC 为目标时的 `TCPI=(BAC-EV)/(BAC-AC)`。
- 项目成本控制九项目标。
- 合同管理五项活动、ADR 与谈判、采购关闭条件。

### 12.3 闭卷自测

> [!question]- 1. 控制质量与确认范围分别关注什么？
> 控制质量关注可交付成果的正确性和质量要求；确认范围关注客户或发起人的正式验收。

> [!question]- 2. 未经控制的范围扩大叫什么？
> 范围蔓延。

> [!question]- 3. 控制进度常用的数据分析技术有哪些？
> 挣值分析、迭代燃尽图、绩效审查、趋势分析、偏差分析、假设情景分析。

> [!question]- 4. 进度压缩的两种方法是什么？
> 快速跟进和赶工。

> [!question]- 5. SV、SPI、CV、CPI 的公式是什么？
> `SV=EV-PV`，`SPI=EV/PV`，`CV=EV-AC`，`CPI=EV/AC`。

> [!question]- 6. 典型偏差和非典型偏差下，ETC 如何计算？
> 原稿给出：非典型偏差 `ETC=BAC-EV`；典型偏差 `ETC=(BAC-EV)/CPI`。

> [!question]- 7. 风险审计的目的是什么？
> 评估风险管理过程的有效性。

> [!question]- 8. 解决合同索赔和争议的首选方法是什么？
> 谈判。
