# 第十一章 规划过程组

## 1. 本章导航

- **本章目标**：掌握规划过程组的作用，以及整合、范围、进度、成本、质量、资源、沟通和风险管理中的重点规划过程。
- **重点小节**：项目管理计划、范围基准与 WBS、进度网络与关键路径、成本基准、资源职责、风险识别与定性分析。
- **关联章节**：[[01-章节笔记/第九章 项目管理基础|第九章 项目管理基础]]、[[01-章节笔记/第十章 启动过程组|第十章 启动过程组]]。
- **材料边界**：本笔记仅覆盖 [[98-原始资料/重点章节|重点章节]] 中第十一章已有内容，止于“实施定性风险分析”，不是第十一章全章复刻。

## 2. 章首速览

规划过程组回答的是“项目准备怎么做”：明确范围、优化目标，并制定实现目标的行动方案。各知识领域分别形成子管理计划、基准和项目文件，最终由“制定项目管理计划”过程协调并整合为综合项目管理计划。

主线可记为：

> 启动授权 → 整合总计划 → 明确范围与 WBS → 把工作变成活动和进度 → 形成成本、质量、资源、沟通与风险安排 → 为执行和监控建立基准。

## 3. 整合管理：制定项目管理计划

### 3.1 规划过程组与制定项目管理计划

- **规划过程组**：明确项目全部范围、定义和优化目标，并为实现目标制定行动方案的一组过程。
- **制定项目管理计划**：定义、准备和协调项目计划的所有组成部分，并整合为一份综合项目管理计划的过程。
- **目的**：生成确定所有项目工作基础与执行方式的综合文件。

![[98-原始资料/图片和附件/a4fd5ce1883cc2b84f721a826592d8e6.png]]

### 3.2 项目管理计划的构成

项目管理计划说明项目的**执行、监控和收尾方式**，主要整合三类组件：

| 类型 | 组成 |
|---|---|
| 子管理计划 | 范围、需求、进度、成本、质量、资源、沟通、风险、采购、干系人管理计划 |
| 基准 | 范围基准、进度基准、成本基准 |
| 其他组件 | 变更管理计划、配置管理计划、绩效测量基准、项目生命周期、开发方法、管理审查 |

事业环境因素强调外部或组织环境约束；组织过程资产强调组织已有的政策、流程、模板、历史信息和经验教训。

## 4. 范围管理

### 4.1 规划范围管理

规划范围管理是创建范围管理计划，记录如何**定义、确认和控制项目范围及产品范围**的过程，作用是为范围管理提供指南和方向。

范围管理计划指导：

1. 制定项目范围说明书。
2. 根据详细范围说明书创建 WBS。
3. 审批和维护范围基准。
4. 正式验收已完成的可交付成果。

范围管理计划可正式或非正式、详细或概括；开发方法说明项目采用预测型、适应型还是混合型。

![[98-原始资料/图片和附件/bcd2ca1e69472bc5dbff9f883b31de00.png]]

### 4.2 收集需求

收集需求是为了实现目标而确定、记录并管理干系人的需要和需求，为定义产品范围和项目范围奠定基础。

| 技术类别 | 方法 |
|---|---|
| 数据收集 | 头脑风暴、访谈、焦点小组、问卷调查、标杆对照 |
| 数据分析 | 文件分析 |
| 决策 | 投票、独裁型决策制定、多标准决策分析 |
| 数据表现 | 亲和图、思维导图 |
| 人际关系与团队技能 | 名义小组技术、观察与交谈、引导 |

六类需求：**业务需求、干系人需求、解决方案需求、过渡和就绪需求、项目需求、质量需求**。

需求跟踪矩阵把产品需求从来源连接到能够满足需求的可交付成果，用于纵向跟踪“来源—目标—范围/WBS—设计开发—测试”，也用于从高层级需求追踪到详细需求。

![[98-原始资料/图片和附件/bc359b5b7dd678be63ee0008be6c85b0.png]]

### 4.3 定义范围

定义范围是制定项目和产品详细描述的过程，重点给出产品、服务或成果的**边界和验收标准**。

项目范围说明书描述：项目范围、主要可交付成果、假设条件和制约因素；详细内容包括产品范围描述、可交付成果、验收标准和项目除外责任。

![[98-原始资料/图片和附件/eeb09d95276acc57464952373645595d.png]]

### 4.4 创建 WBS

创建 WBS 是把项目可交付成果和项目工作分解成较小、更易管理的组件，为交付内容提供架构。

- **WBS**：团队为实现项目目标、创建所需可交付成果而需要实施的全部工作范围的层级分解。
- WBS 组织并定义项目总范围，最底层是**工作包**。
- 此处“工作”指作为活动结果的工作产品或可交付成果，而非活动本身。

分解步骤：

1. 识别和分析可交付成果及相关工作。
2. 确定 WBS 的结构和编排方法。
3. 自上而下逐层细化分解。
4. 为组成部分制定并分配标识编码。
5. 核实分解程度是否恰当。

编制原则：面向可交付成果、符合项目范围、底层支持计划和控制、每个元素唯一责任人、通常控制在 4—6 层、纳入项目管理和分包工作、主要干系人参与、允许随正式变更演进。下一级必须 **100%** 代表上一级，一个工作单元只能从属于一个上层单元。

![[98-原始资料/图片和附件/b132622d3d1cfd0b02b3c944cd44a82d.png]]

### 4.5 范围基准与 WBS 层级

范围基准是经过批准的**项目范围说明书、WBS 和 WBS 字典**，只能通过正式变更控制程序变更，用作比较基础。原稿还在 WBS 说明中列出工作包和规划包；辨识时仍以三项正式构成为主。

| 组件 | 位置与作用 |
|---|---|
| 控制账户 | 管理控制点，整合范围、预算和进度；包含两个或以上工作包，每个工作包只关联一个控制账户 |
| 规划包 | 低于控制账户、高于工作包；当前已知但尚未分解为详细活动的工作 |
| 工作包 | WBS 最底层，带有唯一标识，可据此估算、安排、执行和控制 |

## 5. 进度管理

### 5.1 规划进度管理与定义活动

规划进度管理是为规划、编制、管理、执行和控制项目进度制定政策、程序和文档。进度管理计划为编制、监督和控制进度建立准则，内容可包括进度模型、发布与迭代长度、精确度、计量单位、WBS、模型维护、控制临界值、绩效测量规则和报告格式。

定义活动是识别和记录完成可交付成果所需具体行动，把工作包分解为进度活动，并需在整个项目期间开展。

- **滚动式规划**：近期工作详细规划，远期工作保持较高层级，是渐进明细方式。
- **里程碑**：项目中的重要时点或事件，持续时间为零，可分强制性和选择性。

### 5.2 排列活动顺序

排列活动顺序是识别并记录项目活动之间关系，把活动列表转化为进度网络图。除开始和结束活动外，每项活动至少有一个紧前活动和一个紧后活动。

**紧前关系绘图法（PDM）**又称前导图法、单代号网络图或活动节点图，节点表示活动：

| 关系 | 判断口径 |
|---|---|
| FS 完成到开始 | 紧前完成，紧后才能开始 |
| FF 完成到完成 | 紧前完成，紧后才能完成 |
| SS 开始到开始 | 紧前开始，紧后才能开始 |
| SF 开始到完成 | 紧前开始，紧后才能完成 |

基本时间关系：`EF = ES + 工期`，`LS = LF - 工期`。

**箭线图法（ADM）**又称双代号网络图或活动箭线图，箭线表示活动，节点表示事件。

- 提前量：紧后活动相对紧前活动可以提前的时间量，通常用负值表示。
- 滞后量：紧后活动相对紧前活动需要推迟的时间量，通常用正值表示。

### 5.3 估算活动持续时间

估算活动持续时间是根据资源估算结果，估算完成单项活动所需工作时段数。需考虑收益递减规律、资源数量、技术进步和员工激励等因素。

| 方法 | 识别词与特点 |
|---|---|
| 类比估算 | 参考类似项目历史参数；快、便宜但准确性较低，信息不足时常用 |
| 参数估算 | 利用历史数据与变量的统计关系或算法计算 |
| 三点估算 | 用乐观、最可能、悲观时间反映不确定性和风险 |
| 自下而上估算 | 细化工作后逐层汇总，通常更细致 |

持续时间估算是工作时段的定量评估，**不包含滞后量**，但可以给出变动区间。

### 5.4 制定进度计划、关键路径与浮动时间

制定进度计划分析活动顺序、持续时间、资源需求和进度制约因素，创建带计划日期的进度模型。

关键路径法在不考虑资源限制时，通过正推和逆推计算 ES、EF、LS、LF：

- 正推：从前往后，工期相加；汇聚节点取较大值。
- 逆推：从后往前，工期相减；分支节点取较小值。
- 关键路径是网络中**持续时间最长的活动路径**，决定项目最短工期。

公式：

- 总浮动时间：`LF - EF` 或 `LS - ES`。
- 自由浮动时间：`紧后活动最早开始时间的最小值 - 本活动最早完成时间`。

![[99-附件/d222d65fef59f9a33b8252994a0fe92a.png]]

### 5.5 资源优化、进度压缩与表示方法

| 技术 | 结果或代价 |
|---|---|
| 资源平衡 | 根据资源制约调整日期，可能改变关键路径 |
| 资源平滑 | 在既定限制内调整活动，不改变关键路径 |
| 赶工 | 投入额外资源，通常增加成本和风险 |
| 快速跟进 | 将本应顺序进行的活动并行，增加返工和风险 |

PERT 使用乐观时间、最可能时间和悲观时间进行三点估算。项目进度计划可用横道图（甘特图）、里程碑图和项目进度网络图表示。

## 6. 成本管理

### 6.1 规划成本管理与估算成本

- **规划成本管理**：确定如何估算、预算、管理、监督和控制项目成本，为全项目期间的成本管理提供指南。
- **估算成本**：对完成项目工作所需资金作近似估算，作用是确定所需资金。

估算成本使用的范围基准包括项目范围说明书、WBS 和 WBS 字典。

### 6.2 制定预算与成本基准

制定预算汇总所有单个活动或工作包的估算成本，建立经批准的成本基准。

成本基准是**经过批准、按时间段分配的项目预算**，不包括管理储备，只能通过正式变更控制变更，是与实际结果比较的依据。动用管理储备时，需先获得变更控制批准，再把相应金额移入成本基准。

![[99-附件/6d954e9d107840ff05c297212413756f.png]]

## 7. 质量管理

规划质量管理识别项目及可交付成果的质量要求或标准，并书面描述如何证明符合要求或标准。它应与其他知识领域的规划过程并行开展。

| 类别 | 技术 |
|---|---|
| 数据收集 | 标杆对照、头脑风暴、访谈 |
| 数据分析 | 成本效益分析、质量成本 |
| 决策 | 多标准决策分析 |
| 数据表现 | 流程图、逻辑数据模型、矩阵图、思维导图 |

质量成本分为**预防成本、评估成本、失败成本**。

## 8. 资源管理

### 8.1 规划资源管理

规划资源管理定义如何估算、获取、建设、管理和控制实物资源及团队资源。

角色职责的三种表现形式：

- **层次型**：组织结构图，自上而下表示关系；包括 WBS、OBS、资源分解结构。
- **矩阵型**：职责分配矩阵（RAM）展示资源在工作包中的任务分配，确保每项任务只有一个负责人。
- **文本型**：详细描述团队成员职责。

资源管理计划说明资源的分类、分配、管理和释放，可分团队管理计划与实物资源管理计划。团队章程包括团队价值观、沟通指南、决策标准与过程、冲突处理、会议指南和团队共识。

### 8.2 估算活动资源

估算活动资源确定执行项目所需团队、设施、设备、材料、用品及其他资源的类型和数量。

- 资源日历：规定具体资源何时可用、可用多久。
- 资源需求：说明各工作包或活动所需资源类型和数量。
- 资源分解结构：按类别和类型对资源作层级展现。

## 9. 沟通管理

规划沟通管理基于干系人信息需求、可用组织资产和项目需要，为沟通活动制定适当方法和计划。应在项目早期形成，并在整个项目期间定期审查和修改。

三类沟通方法：

- **互动沟通**：参与者实时或多向交换信息。
- **推式沟通**：把信息直接发送给特定接收者，但不保证其已理解。
- **拉式沟通**：接收者按需自行访问信息，适合大量或复杂信息。

沟通管理计划至少明确：沟通需求、信息内容、上报步骤、发布原因、回应时效与频率、负责人、保密信息授权人，以及接收群体的需求和期望。

## 10. 风险管理

### 10.1 规划风险管理

规划风险管理定义如何实施项目风险管理活动，使风险管理水平、方法和可见度与项目风险程度及项目重要性匹配。

项目风险有两个层面：

1. **单个项目风险**：可能影响某个项目目标的不确定事件或条件。
2. **整体项目风险**：单个风险与其他不确定性来源联合，对项目整体产生的影响。

风险既可能是负面的威胁，也可能是正面的机会。风险管理计划包括策略、方法论、角色与职责、资金、时间安排、风险类别、风险偏好、概率和影响定义、概率和影响矩阵、报告格式及跟踪安排。

### 10.2 识别风险

识别风险是识别单个项目风险及整体项目风险来源，并记录风险特征。主要输出包括：

- **风险登记册**：已识别风险清单、潜在风险责任人、潜在应对措施。
- **风险报告**：整体项目风险来源，以及已识别单个项目风险的概述；采用渐进方式编制。

### 10.3 实施定性风险分析

实施定性风险分析通过评估单个风险的发生概率、影响和其他特征，对风险进行优先级排序，为后续分析或行动提供基础，并为风险指定责任人。

风险登记册可更新：概率和影响评估、优先级或风险分值、责任人、紧迫性、风险类别、低优先级观察清单及待进一步分析的风险。风险报告更新最重要的单个风险、全部风险的优先级列表和简要结论。

## 11. 章末综合复习

### 11.1 核心对比

| 易混项 | 区分 |
|---|---|
| 项目章程 / 项目管理计划 | 章程授权项目与项目经理；管理计划说明如何执行、监控和收尾 |
| 产品范围 / 项目范围 | 产品范围关注成果特性；项目范围关注交付成果所需全部工作 |
| WBS / 活动清单 | WBS 面向可交付成果；活动清单描述完成工作包所需行动 |
| 范围基准 / 成本基准 | 范围基准是范围说明书、WBS、WBS 字典；成本基准是按时间分配且不含管理储备的批准预算 |
| 总浮动 / 自由浮动 | 总浮动关注不延误项目或制约目标；自由浮动关注不延误紧后活动最早开始 |
| 资源平衡 / 资源平滑 | 平衡可能改变关键路径；平滑不改变关键路径 |
| 赶工 / 快速跟进 | 赶工增加资源和成本；快速跟进改并行并增加返工风险 |
| 风险登记册 / 风险报告 | 登记册记录单个风险明细；报告汇总整体风险及重要风险概况 |

### 11.2 必须准确记忆

- 项目管理计划的三类组成：子管理计划、三大基准、其他组件。
- 六类需求及需求跟踪矩阵的连接作用。
- WBS 定义、分解步骤、100% 规则与三个层级组件。
- PDM 四种依赖关系、关键路径判断和两类浮动时间公式。
- 资源优化与进度压缩的四种技术及影响。
- 成本基准不含管理储备。
- 三类沟通方法。
- 单个风险与整体项目风险、风险登记册与风险报告。

### 11.3 闭卷自测

> [!question]- 1. 项目管理计划由哪三类组件构成？
> 子管理计划、基准和其他组件。

> [!question]- 2. 范围基准的三个正式组成部分是什么？
> 项目范围说明书、WBS、WBS 字典。

> [!question]- 3. WBS 的最底层是什么？100% 规则表示什么？
> 最底层是工作包；所有下一级元素必须完整且不重不漏地代表上一级范围。

> [!question]- 4. FS、FF、SS、SF 分别表示什么？
> 完成到开始、完成到完成、开始到开始、开始到完成。

> [!question]- 5. 总浮动时间和自由浮动时间如何计算？
> 总浮动时间 = LS - ES = LF - EF；自由浮动时间 = 紧后活动最早开始时间最小值 - 本活动最早完成时间。

> [!question]- 6. 哪一种资源优化技术可能改变关键路径？
> 资源平衡；资源平滑不改变关键路径。

> [!question]- 7. 赶工和快速跟进的代价分别是什么？
> 赶工通常增加成本和风险；快速跟进增加返工和风险。

> [!question]- 8. 成本基准是否包含管理储备？
> 不包含。经批准动用管理储备后，才把相应金额移入成本基准。

> [!question]- 9. 规划沟通管理中的三类沟通方法是什么？
> 互动沟通、推式沟通、拉式沟通。

> [!question]- 10. 风险登记册与风险报告分别记录什么？
> 登记册记录单个风险、责任人和潜在应对等明细；风险报告记录整体风险来源和重要单个风险概述。
